# Code of Conduct

Arkeyan Launcher is made by and for Skylanders fans. In its issues, pull requests, discussions and Discord:

- Be respectful and patient, with newcomers above all. Criticise code and ideas, never people.
- No harassment, insults, discrimination, or personal attacks, and no sharing of someone's private information.
- No piracy: never share or ask for disc images, game files or download links for them.
- Stay on topic, and keep reports factual.

## Contributions and AI tools

You may use AI tools to write code, tests or documentation. The project does not care how a change was written. It
cares about who submits it, and that person is its author.

1. You understand what you submit. You can explain any line of your pull request, why it is there and how you tested
   it, without going back to the tool. Reviewers may ask. If you cannot answer, the pull request is closed.
2. You checked it. It builds, tests and checks pass, and you ran the change yourself. Generated code that nobody has
   run is not a contribution.
3. The description is true. It says what you actually changed and tested; no invented test results, no generated
   filler.
4. You can justify where it comes from. Do not submit anything whose license you cannot justify, including code an AI
   tool reproduced. Nothing may come from the games or from another project (Xenia, ReXGlue, Unleashed Recompiled,
   Dolphin, RPCS3 or any other): no code, assets or texts, even rewritten by a tool. By submitting, you agree that your
   contribution is licensed under the MIT license, like the rest of the project.
5. You answer for it. If a contribution turns out to be a problem (a bug, a security flaw, a license violation,
   malicious code), its author is held solely responsible. "The AI wrote it" is not an excuse: a tool is never a
   contributor.
6. You keep game data and secrets out of AI tools. Never paste into an AI tool, or any other outside service, anything
   from a game (disc images, game files, translated code, shader caches, dumps, figure data) or a secret (signing keys,
   tokens, passwords). The same goes for issues and pull requests. This applies to everyone, maintainers first.
7. Large changes start with an issue. Before a large pull request (a new feature, a broad refactoring, or several
   hundred changed lines), especially one generated by an agent, open an issue and agree on the approach. Large pull
   requests that arrive unannounced may be closed without review. Maintainers follow the same rule for their own large
   changes.

You don't have to declare that you used an AI tool. The rules are the same either way.

Being responsible does not mean being punished for every mistake:

- Bugs happen to everyone. You will be asked to help fix yours, nothing more.
- If you keep submitting code you do not understand or have not tested, your pull requests may be closed without
  review.
- If game data or a secret reaches an outside service, tell the owner at once: the secret is changed. Hiding it, or
  doing it again, leads to a ban.
- Malicious code (malware, backdoors, data theft, a hidden or hijacked dependency) or a deliberately misleading change
  leads to a permanent ban, removal of your contributions and a report to GitHub.

The owner moderates: a message or a contribution that breaks these rules can be edited or removed, and its author warned,
then blocked from the project. To report a problem, contact the owner privately on the
[Discord](https://discord.gg/UMQY4SAS3F).
